# NotebookLM 슬라이드 (기본 산출물 · 9단계)

완성된 `index.html` 을 NotebookLM 소스로 넣고, **NotebookLM 이 자기 디자인으로 만든**
슬라이드를 PPTX·PDF 로 받는다. 원본의 내용·순서·장수를 유지한다.

8단계(html2pptx)와 목적이 다르다. **둘 중 하나를 고르는 게 아니라 둘 다 만든다.**

| | 8단계 html2pptx | 9단계 nlm2deck |
|---|---|---|
| 디자인 | 내 덱 그대로 | NotebookLM 이 새로 |
| 글자 편집 | **된다** (텍스트 상자·도형) | **안 된다** (슬라이드 = PNG 한 장) |
| 걸리는 시간 | 10초 안팎 | 40~120분 |
| 필요한 것 | 파이썬 패키지 | 구글 로그인 + 생성 할당량 |
| 인터넷 | 필요 없음 | 필요함 |

## 언제 만드나

**항상 만든다.** 요청을 기다리지 않는다. 8단계 PPTX 가 끝나면 바로 이어서 돌린다.

건너뛰는 경우는 셋뿐이다. 어느 쪽이든 **이유를 사용자에게 보고한다.**

- 로그인이 안 돼 있고 사용자가 로그인을 원치 않을 때
- `notebooklm` CLI 또는 크롬이 없을 때
- 사용자가 "건너뛰어", "시간 없어"라고 명시했을 때

## 먼저 사용자에게 알릴 것

시작하면서 세 가지를 말한다. **알리는 것이지 허락을 구하는 것이 아니다** — 말해두고
바로 시작한다. 다만 사용자가 멈추라고 하면 즉시 멈춘다.

1. **결과 PPTX 는 글자를 못 고친다.** 슬라이드마다 이미지 한 장이다. 문구 수정이
   필요하면 8단계 PPTX 를 쓰면 된다. 두 벌 다 있으니 손해가 아니다.
2. **40~120분 걸린다.** 덩어리 수와 레이트 리밋에 달렸다. 배경으로 돌리고 다른
   일을 계속한다.
3. **구글 계정 로그인이 필요하고, 로그인은 사용자가 직접 해야 한다.**

## 로그인 (사용자가 직접)

브라우저가 열리는 구글 OAuth 다. **에이전트가 대신 하지 않는다.** 사용자에게 이
명령을 실행하게 한다:

```bash
notebooklm -p <프로필> login
```

유료 계정을 따로 쓰려면 프로필을 나눈다(`-p pro` 등). `run.sh --profile pro`.

**`notebooklm auth check` / `doctor` 의 결과를 믿지 않는다.** 세션이 만료된 상태에서도
"유효함"이라고 답한 적이 있다. `run.sh` 는 `notebooklm list` 를 실제로 호출해 확인한다.

인증 확인이 한 번 실패해도 곧바로 로그인을 안내하지 않는다. 순간 장애로도 떨어지기
때문에 3회 재시도하고, 그래도 안 되면 **실제 오류 문구를 보여준 뒤** 인증 관련 문구가
있을 때만 로그인을 권한다. 어떤 오류든 "로그인하세요"로 뭉뚱그리면 멀쩡한 세션을
다시 만들게 만든다.

## 실행

```bash
bash "$SKILL_DIR/assets/nlm2deck/run.sh" "lectures/<slug>/index.html" --profile <프로필>
```

| 옵션 | 뜻 |
|---|---|
| `--profile <이름>` | notebooklm CLI 프로필 (기본 `default`, 또는 `NOTEBOOKLM_PROFILE`) |
| `--max <N>` | 덩어리 최대 페이지 (기본 20) |
| `--jobs <N>` | 동시 실행 워커 수 (기본 3) |

산출물:

```
lectures/<slug>/
  <slug>-notebooklm.pptx     합본 (NotebookLM 디자인, 이미지)
  <slug>-notebooklm.pdf      합본 PDF
  notebooklm-chunks/         source.pdf · plan.tsv · 덩어리 원본 · 노트북 ID
```

중간에 끊겨도 **다시 실행하면 이어서 한다.** 이미 받은 덩어리는 건너뛰고, 만들어둔
노트북은 재사용한다.

## 20장 규칙 — 왜 쪼개나

NotebookLM 은 소스가 크면 페이지를 1:1 로 옮기지 않고 **요약해서 압축한다.**

| 넣은 것 | 나온 것 |
|---|---|
| 42페이지 통째로 | **21장** |
| 5 / 6 / 8 / 7 / 6 / 10 페이지로 나눠서 | **5 / 6 / 8 / 7 / 6 / 10 장** |

그래서 **20장을 넘는 덱은 쪼갠다.** `split_pdf.py` 가 자동으로 판단한다.

- **경계는 파트에 맞춘다.** `.eyebrow` 가 `PART …` / `SECTION …` / `파트 …` 로 시작하는
  슬라이드를 파트 시작으로 본다. 파트 중간을 자르면 NotebookLM 이 없는 맥락을
  지어낸다. 표식이 없는 덱이면 `--boundaries 1,6,12,20,27` 로 직접 준다.
- **덩어리 상한은 기본 20페이지다.** 20장까지는 1:1 로 옮기고 넘으면 압축한다.
  분할 기준과 상한이 같은 값인 이유다. `--max` 로 올리면 노트북 수와 시간은 줄지만
  압축을 자초하는 것이다.
- 압축이 일어나면 `merge_chunks.py` 대조표에 `← 압축됨` 이 찍히고 종료 코드가 1이 된다.
  그 덩어리만 `--max` 를 낮춰 다시 돌린다.

## 레이트 리밋

슬라이드 생성은 구글이 **계정 단위**로 막는다(`RATE_LIMITED`). 6개를 동시에 띄웠더니
3개가 통과하고 3개가 막혔다. 순차로 바꾸고 짧게 3회 재시도한 것도 실패했다 —
할당량이 열리기 전에 재시도가 끝났기 때문이다.

그래서 워커는 **5분 간격으로 최대 2시간** 문을 두드린다. 로그에
`[C4] 레이트 리밋 대기 (시도 3/24)` 가 반복되는 건 정상이다. 죽은 게 아니다.

## 실행 후 반드시 확인할 것

`merge_chunks.py` 가 찍는 대조표를 **그대로 사용자에게 전한다.** 조용히 넘어가지 않는다.

```
  덩어리   원본 슬라이드   입력   출력
  C1       S01–S05         5     5
  C2       S06–S11         6     6
  합계                      11    11
```

| 신호 | 뜻과 대응 |
|---|---|
| `← 압축됨` | 그 덩어리가 1:1 이 아니다. `--max` 를 낮춰 그 구간만 다시 만든다 |
| `!! PDF 와 PPTX 장수가 다르다` | 다운로드가 일부만 됐다. 해당 덩어리 파일을 지우고 재실행 |
| `임베드 이미지 해상도: {(1376, 768)}` | 정상. 값이 여럿이면 덩어리마다 해상도가 다른 것이니 알린다 |
| `!! 텍스트가 거의 없다` (렌더 단계) | 소스 PDF 가 이미지로 구워졌다. NotebookLM 이 내용을 못 읽는다. 원인을 찾고 다시 굽는다 |
| `!! 페이지와 슬라이드 수가 다르다` | 세로 스택이 있으면 정상일 수 있다. 눈으로 확인한다 |

그리고 **파워포인트로 실제로 열어** 복구 경고가 없는지, 순서가 맞는지 본다.

## 뒷정리

덩어리마다 노트북이 하나씩 생긴다(6덩어리 = 노트북 6개). 계정에 쌓이므로 끝나면
사용자에게 정리할지 묻는다. ID 는 `notebooklm-chunks/C*.notebook` 에 있다.

```bash
notebooklm -p <프로필> delete <노트북ID>
```

**묻지 않고 지우지 않는다.**

## 의존성

- `notebooklm` CLI (notebooklm-py) + 로그인된 프로필
- 헤드리스 크롬 또는 엣지. 못 찾으면 `LECTURE_DECK_CHROME` 에 경로를 준다
- `pymupdf` · `python-pptx`

기본 단계지만, 없으면 이 단계만 건너뛰고 이유를 알린다. 덱과 다른 산출물은 영향 없다.
**"어차피 선택 산출물이니까"라며 조용히 넘기지 않는다.**
