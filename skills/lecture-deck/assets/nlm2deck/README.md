# nlm2deck — 덱 HTML 을 NotebookLM 에 넣어 슬라이드를 다시 받기

`index.html` 을 NotebookLM 소스로 넣고, NotebookLM 이 자기 디자인으로 만든
슬라이드를 PPTX·PDF 로 받는다. 내용·구조·장수는 원본을 따라간다.

`html2pptx` 와 목적이 다르다. html2pptx 는 **내 디자인 그대로, 글자를 고칠 수 있게**
옮긴다. nlm2deck 은 **NotebookLM 디자인으로, 이미지로** 받는다. 둘은 대체재가
아니라 별개 산출물이다.

## 파이프라인

```
index.html
  │  render_pdf.py     헤드리스 크롬 + reveal 의 ?print-pdf
  ▼
source.pdf (텍스트 살아 있음)
  │  split_pdf.py      20장 초과면 파트 경계로 쪼갬 → C1.pdf … Cn.pdf + plan.tsv
  ▼
덩어리 PDF
  │  chunk_worker.sh   덩어리마다 노트북 하나 → 소스 추가 → 생성 → 다운로드 (병렬)
  ▼
Cn.pptx / Cn.pdf.out
  │  merge_chunks.py   plan.tsv 순서대로 이어붙임
  ▼
<slug>-notebooklm.pptx / .pdf
```

`run.sh` 가 이 넷을 순서대로 부른다.

## 왜 쪼개나 — 실측

42장 덱을 통째로 넣었더니 NotebookLM 이 **21장으로 압축**했다. 같은 덱을 파트
경계로 쪼개 따로 만들었더니 여섯 덩어리 전부 1:1 로 나왔다.

| 입력 | 출력 |
|---|---|
| 42페이지 통째로 | 21장 |
| 5 / 6 / 8 / 7 / 6 / 10 페이지 | 5 / 6 / 8 / 7 / 6 / 10 장 |

**경계는 20장이다.** 20장까지는 1:1 로 옮기고 넘으면 압축한다. 그래서 분할 기준과
덩어리 상한이 둘 다 20이다. `--max` 로 올릴 수 있지만 올린 만큼 압축을 자초하는
것이다. 압축되면 `merge_chunks.py` 가 표에서 `← 압축됨` 으로 집어낸다.

## 각 스크립트

| 파일 | 하는 일 |
|---|---|
| `run.sh` | 전체 오케스트레이션. 인증 확인 → 렌더 → 분할 → 병렬 생성 → 합본 |
| `render_pdf.py` | 덱 폴더를 로컬 서버로 열고 `?print-pdf` 를 크롬으로 인쇄. 페이지 수·텍스트량 검증, 꼬리 빈 페이지 제거 |
| `split_pdf.py` | 파트 경계 감지 후 상한 안에서 그룹핑. `plan.tsv` 기록 |
| `chunk_worker.sh` | 덩어리 하나를 끝까지. 재실행 안전 |
| `merge_chunks.py` | 원본 PNG 바이트를 그대로 꺼내 재조립. 입출력 대조표 출력 |
| `nlm.sh` | notebooklm CLI 재시도 래퍼 (SSL 오류에만) |
| `pick.py` | JSON 필드 추출 |

## 설계상 유의점 (전부 실제로 데인 것)

- **HTML 은 소스로 못 넣는다.** NotebookLM 이 받는 건 PDF·텍스트·마크다운·EPUB·Word 다.
  그래서 PDF 가 중간 형식이다. 이미지 캡처 PDF 를 넣으면 NotebookLM 이 내용을 못
  읽으므로 `render_pdf.py` 가 텍스트 추출량을 확인한다.
- **`index.html` 을 고치지 않는다.** reveal 4.x 는 `?print-pdf` 로 인쇄 모드를 켜므로
  파일을 건드릴 이유가 없다.
- **reveal 인쇄는 끝에 빈 페이지를 한 장 붙일 때가 있다.** 꼬리만 잘라내고 몇 장
  잘랐는지 찍는다.
- **`artifact wait` 을 쓰지 않는다.** RPC 오류로 0.1초 만에 조용히 반환해 아직 없는
  산출물을 받으러 가게 만든 적이 있다. 직접 폴링한다.
- **CLI 의 자기 보고를 믿지 않는다. API 에 직접 물어 확인한다.** 이 한 줄 때문에
  세 번 데였다:
  - `auth check` 가 만료된 세션에도 "유효함"이라고 답했다 → `list` 를 실제로 호출한다.
  - 소스 추가 명령 이름을 `add_file` 로 잘못 알고 있었다(실제는 `source add`).
    출력을 `/dev/null` 로 버려서 `No such command` 를 못 보고, 빈 노트북으로
    15분간 인덱싱을 기다렸다.
  - 이름을 고친 뒤에는 `source add` 가 **업로드에 성공하고도** asyncio 트레이스백
    (`AssertionError: Data should not be empty`)을 뱉고 0 이 아닌 코드를 반환해서,
    멀쩡히 올라간 소스를 실패로 판정했다.

  결론: 성공 판정은 stdout·종료 코드가 아니라 `source list` 로 소스가 실제로
  존재하는지 확인해서 내린다.
- **셸 안에 파이썬 인라인 파서를 넣지 않는다.** 따옴표 충돌로 45회 연속 SyntaxError 를
  내면서도 스크립트는 계속 진행했다. 그래서 `pick.py` 가 별도 파일이다.
- **슬라이드 생성은 계정 단위 레이트 리밋이 있다.** 6개를 동시에 띄웠더니 절반이
  `RATE_LIMITED` 로 막혔다. 기본 동시 실행 3개, 시작 시각 40초씩 엇갈림, 워커는
  5분 간격으로 최대 2시간 재시도한다.
- **덩어리마다 노트북을 따로 만든다.** 한 노트북에 여러 덩어리를 넣으면 다른
  덩어리의 내용이 섞여 들어온다.
- **결과 PPTX 는 슬라이드마다 PNG 한 장이다.** 텍스트 상자·런·노트가 전부 0이라
  파워포인트에서 글자를 못 고친다. 합본은 그 PNG 를 **원본 바이트 그대로** 옮기므로
  화질 손실은 없다.
