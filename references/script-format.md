# 강사 대본 양식 (script.md)

## 대본은 두 곳에 동시에 존재한다

같은 대본이 두 군데에 들어가고, **둘의 슬라이드 번호·내용은 일치해야 한다**:

1. **각 슬라이드의 `<aside class="notes">`** — reveal.js 발표자 뷰(`S` 키)에서 현재 슬라이드 옆에 뜬다. 발표 중 실시간으로 본다.
2. **독립 `script.md`** — 슬라이드를 안 열어도 처음부터 끝까지 읽으며 흐름을 파악·연습하는 대본.

덱을 만들 때 `aside.notes`에 넣은 말과 `script.md`에 적은 말이 어긋나면 안 된다. 한쪽을 고치면 다른 쪽도 고친다.

## script.md 구조

슬라이드마다 한 블록:

```
## 슬라이드 N — {슬라이드 제목}
{그 슬라이드에서 실제로 할 말 2~5문장.}
(선택) 큐: {강조/시연/판서 등 행동 지시}
```

- 헤더는 반드시 `## 슬라이드 N — 제목` 형식 (N은 덱 순서와 일치).
- 본문은 실제로 입 밖에 낼 문장. 요약이 아니라 "말"을 적는다.

## 주장·출처 연결 표식

사실 주장이 있는 슬라이드는 HTML과 `script.md`에 같은 강의 전용 표식을 둔다. 이 표식은 패키징 전 검증용이며 STUDENT에서는 제거된다.

```html
<!-- ld:slide {"id":"S001","title":"슬라이드 제목","claims":[{"id":"C001","mode":"established","sources":["R1","R2"]}]} -->
<section>
  ...
  <aside class="notes">실제로 할 말.
Claim C001; evidence R1, R2
[R1] 출처 제목 — 발행처 — 2026 — https://공개-출처
[R2] 출처 제목 — 발행처 — 날짜 미표기 — https://공개-출처</aside>
</section>
<!-- ld:end S001 -->
```

`script.md`의 같은 슬라이드 블록에도 시작·종료 표식과 아래 줄을 그대로 둔다:

```text
Claim C001; evidence R1, R2
[R1] 출처 제목 — 발행처 — 2026 — https://공개-출처
[R2] 출처 제목 — 발행처 — 날짜 미표기 — https://공개-출처
```

- `C001`은 주장 ID, `R1`은 공개 출처 ID다. 하나의 주장에 여러 출처를 연결할 수 있다.
- HTML 표식, 발표자 노트, `script.md`의 C→R 연결은 같아야 한다.
- 근거가 없는 진행·실습 슬라이드는 `"claims":[]`를 쓰며 `Claim ...` 줄을 넣지 않는다.
- `established`는 확인된 주장, `limited`는 범위를 제한한 주장, `uncertainty`는 불확실성·반박을 명시한 주장에만 쓴다.
- 표식과 출처 줄은 위의 단순 형식을 유지한다. 강사 메모 안에 HTML 태그를 넣지 않는다.

## 말투

- **구어체.** 글말("~이다")이 아니라 말("~예요 / ~해볼게요")로.
- 한 슬라이드당 **30~90초** 분량 (보통 2~5문장).
- 청중에게 말 거는 톤: 질문·확인("여기까지 따라오셨나요?")을 섞는다. 단, 매 슬라이드마다 반복하면 빈말이 된다 — 트랙당 1~2번.

### 강사 대본의 3대 함정 (anti-slop · 자세한 22개는 `anti-slop.md`)

`script.md`는 lecture-deck 산출물 중 AI slop이 가장 심하게 묻어나는 곳이다. 다음 셋만 의식하면 대본이 즉시 사람 말처럼 들린다:

**1. 시그포스팅 (Signposting) ★ 가장 흔함**
- 나쁨: "지금부터 ~을 알아보겠습니다 / 이번 슬라이드에서는 ~을 다룹니다 / 자, 그럼 시작해볼까요?"
- 좋음: 본문으로 바로 진입. 슬라이드 제목이 이미 시그포스다.

**2. 아첨 (Sycophancy)**
- 나쁨: "정말 좋은 질문이에요! / 여러분 잘하고 계세요! / 멋진 발견이에요!"
- 좋음: 질문에 바로 답. 칭찬은 강의 전체에서 1~2번만, 진심으로.

**3. 일반론 마무리 (Generic conclusion) ★ closing 슬라이드 직격탄**
- 나쁨: "미래가 밝습니다 / 함께 나아갑시다 / 흥미진진한 여정이 시작됩니다"
- 좋음: "월요일 출근하자마자 ○○를 켜세요. 30분 안에 첫 결과가 나옵니다."

### 한국어 특화 함정 2개

- **응원체**: "오늘도 화이팅! / 함께 해봐요!" → 행동 지시만.
- **챗봇 인사 잔재**: "도움이 되셨길 바랍니다 / 더 궁금한 점이 있으시면" → 통째로 삭제.

대본을 다 쓴 후 `anti-slop.md`의 체크리스트(특히 14·16·17·20·22번)를 한 번 훑는다.

## 예시 (슬라이드 2장 분량)

## 슬라이드 1 — 표지
안녕하세요. 오늘은 코드 한 줄 안 쓰고, 진짜 동작하는 결과물 하나를 같이 만들어 갈 거예요. 우리가 할 일은 딱 하나 — 좋은 아이디어를 한 페이지로 잘 정리하는 것뿐입니다.
큐: 미리 만들어둔 완성본을 화면에 띄워두고 시작.

## 슬라이드 2 — 오늘 만들 것
자, 결과부터 보여드릴게요. 이게 오늘 끝나면 여러분 손에 들려 있을 물건입니다. 화면 왼쪽이 결과물이고, 오른쪽이 그게 하는 일 세 가지예요. 지금은 "이런 걸 만든다"만 기억하시면 됩니다. 어떻게 만드는지는 잠시 뒤에.
큐: 왼쪽 카드 → 오른쪽 불릿 순서로 손짓하며.

---

`aside.notes` 안에는 위 블록의 본문(+큐)을 그대로 넣는다. 예:
```html
<aside class="notes">자, 결과부터 보여드릴게요. … 큐: 왼쪽 카드 → 오른쪽 불릿 순서로.</aside>
```
