# 핵심 인터뷰 질문 뱅크

## 규칙

- **`AskUserQuestion`으로 핵심 3~4개를 한 번에 묻는다.** 한 문항씩 왕복하지 말 것.
- **객관식 우선** (보기 제공), 직접 입력도 허용. 답이 모이면 바로 브리프+아웃라인 초안으로 넘어간다.
- 주제 성격에 따라 4번째 문항을 변형한다(아래 "주제별 변형").

## 4개 코어 질문 + 보기 예시

**1. 대상 청중·수준**
- 입문 (해당 분야 처음)
- 실무자 (써봤지만 체계 없음)
- 전문가 (심화/최신만)
- (축) 비전공 ↔ 전공

**2. 강의 시간·분량** → 슬라이드 장수로 매핑
| 강의 길이 | 권장 슬라이드 수 |
|---|---|
| 10분 | ≈ **8장** |
| 20분 | ≈ **12장** |
| 30분 | ≈ **15장** |
| 60분 | ≈ **25장** |
> 보기로 "10분 / 20분 / 30분 / 60분"을 주고, 고른 길이에 맞춰 아웃라인 장수를 잡는다.

**3. 끝나고 할 수 있어야 하는 것 (학습 목표 / 결과물)**
- 보기 예: "개념을 설명할 수 있다" / "직접 하나 만들 수 있다" / "내 업무에 적용할 수 있다" / "도구를 세팅하고 첫 실행" — + 직접 입력.
- 모호한 "이해한다"는 피하고 구체적 동사로 유도.

**4. 톤·형식**
- 개념 설명형 ↔ 실습 따라하기형
- 진지/포멀 ↔ 캐주얼/유머

## 주제별 변형 가이드

- **기술·실습 주제** (코딩, 도구 사용 등): 4번 톤 질문에 더해 **"코드/도구 환경"** 질문을 추가한다 — 어떤 언어·툴·OS를 전제할지, 실습 환경이 준비돼 있는지.
- **개념·교양 주제** (역사, 비즈니스, 인문 등): "코드/도구 환경" 자리를 **"사전 지식"** 질문으로 치환한다 — 청중이 미리 알고 있다고 가정할 배경 지식 수준.
- 답변이 애매하면 한 번 더 좁히되, 인터뷰는 최대 2라운드를 넘기지 않는다.
